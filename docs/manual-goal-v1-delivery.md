## Implemented boundary

`GET /api/goals/manual-v1?action=capabilities|context|header|list|lookup|discover` and `POST /api/goals/manual-v1?action=register|submit|close|ack` call the single owner-authorized `goal_manual_v1(action,payload)` RPC. Auth identity is checked by the existing API wrapper and again inside the fixed-projection database function. No caller owner, arbitrary SQL or projection is accepted. Responses use `ok/data/error`, private/no-store. Unsupported or unavailable contracts never fall back to the legacy create/raw-read route.

- Register: operationId, fixed operationType `goal.create.manual`, contractVersion 1, payloadDigest and optional signed reviewToken. Submit: same identity/type/version plus only title/category/description/endDate. PostgreSQL repeats canonical validation and verifies the digest inside the protected transaction; the TypeScript codec and Swift codec use the same RB4 golden vectors.
- Exact receipt: ownerId, operationId/type/version, state, decimal revision, admissionDeadline, optional reason, currently authorized goalId, initial goalVersion and terminalAt. Generic recovery survives missing Goal/profile data. Discovery omits resource IDs and authored content, uses 50/default and 100/max, signed owner-bound 15-minute cursors, a commit-ordered owner counter/barrier and an indexed outstanding summary that includes unacknowledged terminal results.
- Signed calendar review contains owner, profile revision and resolver identifier, expires after 15 minutes and contains no authored date. Submit locks profile configuration and validates the selected calendar date against the actual current profile-local day. Undated creation has no profile dependency. PostgreSQL timezone catalog is the initial resolver (`postgres-tz-v1`); catalog upgrade discipline remains a rollout obligation.
- Canonical new rows: DATE end_date plus explicit date_contract_version 1 and known/no_date state, NULL legacy deadline, initial version and immutable operation/provenance linkage. Active/private/manual, no project/space/community association, no child inserts. Receipts and Goal/provenance are atomic. New-ID registration, close and submit share the same operation uniqueness/fence. No durable content queue, lease or retry worker.
- Header envelope: ownerId, headerContractVersion 1, header and dateContext. The concrete compact projection includes category/progress for existing Goal row rendering and description only on direct detail; it is an intentional small extension of the earlier minimum-header recommendation. No child resources, counts or nested hydration. Legacy rows explicitly return needs_review for any timestamp, or legacy_no_date for NULL, with unchanged stored bytes; no inferred calendar date or intent. Row revisions increment on existing writes without changing date meaning.
- List envelope: ownerId, contractVersion 1, compact items, one dateContext, hasMore/nextCursor. Active default; Paused/Completed/Expired/Archived filters map known database spellings. Keyset order is created_at/id, with a signed owner/status-bound upper-time barrier and 15-minute cursor expiry. Rows reflect current status at each read; this is not a frozen historical membership snapshot. Client uses 50-row pages, retains at most 200 rows per window, then offers refresh. Direct-ID detail retention is capped at 32 recently loaded Goals. Later-page failure retains earlier rows and a retry; direct-ID content is not pruned by page omission.

The Swift store retains one create draft in memory. Only owner/operation/type identifiers are atomically written locally before registration. A failed/malformed registration never permits content dispatch. Explicit retry uses the same frozen in-memory binding; after restart only status/close are available. Terminal outcomes must be surfaced/handled before acknowledgment and replacement creation. Discovery is mandatory even without a local identifier. Account reset clears memory/identifiers and invalidates callbacks; every bound transport dispatch and same-owner 401 replay checks identity generation.
